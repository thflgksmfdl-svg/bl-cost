# BL 작업비 정산

BL을 입력하면 중판에서 한 번 조회하고, 확정된 청구부터 구글시트에 자동 반영하는 정산 서비스입니다. 직원 로그인 없이 접속하며, 주소에 접근한 사람은 청구 정보를 조회·수정할 수 있습니다.

## 사용

1. 사이트에 접속합니다. 직원 로그인은 사용하지 않으며, 검색엔진 색인은 요청하지 않습니다.
2. 처음 입력한 BL만 중판에서 한 번 조회합니다. 조회 시점과 원본을 DB에 보관하고, 추가 결정이 필요 없는 청구부터 자동으로 시트에 저장·검산합니다. 이미 조회한 BL은 저장된 결과를 엽니다.
3. `추가 비용 결정`에 나온 OPP·별도 비용 메모만 처리합니다. 결정 저장 즉시 DB와 시트가 자동 갱신됩니다. 규칙이 정해진 박스 초과비는 자동 계산합니다.
4. 미확정 주문은 고객 청구에서 보류합니다. 같은 주문의 예전 청구 행이 있으면 최종금액을 0원으로 보류하고, 결정이 끝난 뒤 실제 확정금액으로 갱신합니다. 다른 확정 주문은 먼저 자동 반영됩니다.
5. `고객에게 청구할 내역`에는 확정된 양수 금액 주문만 표시됩니다. 시트 저장·검산이 완료된 후 청구 문구를 복사해 결제 링크와 함께 전달합니다. 별도의 최종 반영 버튼은 없습니다.
6. 화면 하단에 실제 저장한 청구 행 수, 신규·기존 갱신 건수, 검산 시각과 저장된 행 바로가기를 표시합니다. 기존 주문은 같은 행을 갱신하며 중복 추가하지 않습니다. 전체 중판 원본은 DB에 보관하고, 시트의 `주문 데이터` 탭을 새로 채우지는 않습니다. 직원은 사이트에서 청구 업무를 진행합니다.
6. `결정 완료`에서 0원 결정도 다시 수정할 수 있습니다. 수정 내용은 자동 반영되며, 실패 시 결정 내역을 보존하고 재시도 버튼을 표시합니다. 저장 작업에서는 중판을 다시 조회하지 않습니다.
7. 계산은 표시된 중판 조회 시점의 원본을 기준으로 합니다. 이후 중판 작업이 바뀌었으면 `최신 중판 내역 다시 조회`를 직접 실행합니다. 이는 기존 추가 비용 결정을 초기화하므로 확인 후 진행하며 이전 기록은 이력에 보관합니다.

## 작업 검산·대시보드

- 상단 메뉴에서 `고객 청구`, `BL별 작업 검산`, `대시보드`를 각각 엽니다. 검산은 무료 주문과 단가 0원 작업을 포함합니다. 하위 주문 수와 상품 행 수를 구분하며, 추가 청구시간은 실제 작업시간에 더하지 않습니다.
- 과거 BL은 기존 시트의 원본/원가 집계를 읽어 보존합니다. 중판 조회를 완료한 같은 BL은 DB 값을 우선 사용하고 과거 값과 차이를 표시합니다. 과거 자료를 다시 조회하거나 기존 원본·원가 행을 덮어쓰지 않습니다.
- `원본·DB 일치`는 저장된 수집 원본과 작업 집계를 대조했다는 뜻입니다. 중판 사이트의 현재 상태를 다시 확인했다는 뜻은 아닙니다. 새 조회 중에는 직전 완성 집계를 시각과 함께 유지합니다.
- `시스템 집계` 탭에 공통 집계 결과를 저장하고, 기존 `BL별 작업 검산`·`대시보드`를 연결합니다. 기존 검산의 P:AF 원본 집계는 남깁니다. 첫 변경 전 두 보고서의 기존 수식은 DB `ReportSnapshot.backup`에 보존합니다. 보고서 저장 후 수량·금액을 다시 읽어 일치해야 새 보고서를 완료로 처리합니다.
- 조회·청구 수정 후 자동 갱신하며, 서버 가동 중 10분마다 시트의 수동 변경을 읽습니다. 즉시 반영하려면 `공유시트 변경 불러오기`를 누릅니다. 이 작업은 중판을 재조회하거나 청구 입력·결제상태·결제일을 수정하지 않습니다.
- 월별 확정 청구는 DB 결정액(중판 조회 BL)과 청구 입력의 최종금액(과거 BL)을 사용합니다. 청구 시트와 차이가 있으면 표시합니다. 과거 BL의 추가 비용 결정 여부는 알 수 없으므로 미확인으로 표시합니다.
- 결제상태 `결제완료`, `미결제`, `보류`를 구분합니다. 빈 값과 알 수 없는 값은 상태 미입력이며 미결제로 단정하지 않습니다. 입금 기록은 해당 작업월 BL에 연결된 청구의 기록이며 입금월별 매출이 아닙니다.
- 원가는 전체 주문을 포함한 참고값입니다. 과거 원가 정산 집계와 조회 당시 단가로 계산한 추정 원가를 구분합니다. CBM·포장재 규격 등 미확정 항목이 있어 실제 마진은 산출하지 않습니다.

운영 점검용 `/admin/`의 관리자 인증은 별도로 유지합니다. 일반 정산 화면에는 계정 관리나 로그인 메뉴를 표시하지 않습니다. 비로그인 사용자의 결정·반영 이력은 공용 사용자로 기록하며 개인별 담당자는 구분하지 않습니다.

## 계산 및 저장 기준

- 중판 하위 주문별로 마지막 금액 칸을 기준으로 무료시간을 적용합니다. 분할 주문은 경고와 무료시간 보정 입력을 제공합니다.
- 작업 종류별 맨 위 기록을 사용하고, 같은 하위 주문·트래킹에 반복되는 내역은 한 번만 합산합니다. 서로 다른 기록은 수집을 중단합니다.
- 박스 10개까지 무료이며 초과분만 자동 청구합니다. OPP 사용이나 금액이 정해지지 않은 비용 메모만 추가 청구 결정을 요구합니다. 수량·무료시간·고객정보가 불명확한 예외는 필요한 정보만 입력합니다.
- 담당자메모는 이미 처리된 기록이므로 새로 수집하거나 화면에 표시하지 않습니다. 추가 비용 판단은 입고오류메시지를 기준으로 하며 부족·파손·출고 요청 등 일반 입고 메모와 무료 범위의 박스 사용은 청구 결정 대상에서 제외합니다.
- 벌크·도장·인쇄스티커는 내부 확인용 0원입니다. 작업비 면제와 전체 면제를 구분합니다. 별도 추가금액은 부가세 포함 원화이며 최종 금액은 기존 기준대로 10원 미만을 버립니다.
- 전체 상품·작업 원본과 청구 결정은 DB에 보존합니다. 화면에는 미결정 예외와 청구할 주문만 전달하며 주문번호를 숫자로 변환하지 않습니다.
- `청구 입력(내가 입력)`에는 최종금액이 양수인 주문만 추가하며 `고객 청구(자동)`의 기존 FILTER에 반영됩니다. 승인 당시 단가·보정 입력은 `시스템 승인기준`에 기록하고 금액은 이를 참조하는 수식으로 저장합니다. 전체 상품을 원본·원가 탭에 다시 쓰지 않습니다.
- 같은 BL의 기존 행은 트래킹 집합이 원본 주문 한 건과 유일하게 연결될 때만 갱신합니다. 기존 청구를 0원으로 수정하면 해당 행도 0원으로 갱신해 자동 청구에서 제외합니다. 다른 BL과 무관한 행은 변경하지 않으며, 기존 0원 행을 새로 늘리지 않습니다.
- 결제상태(AA)·결제일(AB)은 자동화가 쓰지 않습니다. 사용자의 결제 기록과 수식을 그대로 보존합니다. 청구할 금액이 없고 기존 행도 없으면 아무 행도 추가하지 않습니다.
- 단가·환율은 조회 시 고정하며, 저장 전 시트의 규칙 버전만 확인합니다. 규칙이 달라지면 중판 재조회 없이 `청구규칙 다시 적용`으로 재계산합니다. 쓰기 응답이 불확실하면 같은 저장 표식을 검산하며 중복 요청하지 않습니다.
- 기존 행 내용은 반영 요청 이력에 보관하고 저장 직전에 재대조합니다. 중복·불명확한 연결이나 요청 후 시트 수정이 발견되면 중단합니다. 반영 요청별 원자적 저장 표식으로 재시도 시 중복을 막으며 새로 수정한 내역은 별도의 요청으로 반영할 수 있습니다. 청구 입력이 기존 자동집계 범위인 14,955행을 넘으면 저장을 중단합니다.

## 배포

Render Docker Web Service에서 이 저장소 `main`을 연결합니다. Dockerfile과 `start.py`가 정적 파일, 마이그레이션, 최초 관리자, 웹 서버와 작업 처리기를 실행합니다.

| 환경변수 | 용도 |
|---|---|
| `DATABASE_URL` | PostgreSQL 연결. 기존 DB의 `bl_cost` 스키마만 사용 |
| `SECRET_KEY` | 충분히 긴 임의 문자열 |
| `BL_COST_ADMIN_USERNAME` | 최초 관리자 아이디 |
| `BL_COST_ADMIN_PASSWORD` | 최초 생성용 비밀번호. 기존 계정 비밀번호를 재설정하지 않음 |
| `JUNGPAN_ADMIN_ID` | 중판 로그인 아이디 |
| `JUNGPAN_ADMIN_PW` | 중판 로그인 비밀번호 |
| `JUNGPAN_ADMIN_PWD2` | 중판 추가 로그인 값 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 지정 시트 편집 권한만 부여한 서비스 계정 JSON |
| `GOOGLE_SPREADSHEET_ID` | 대상 시트 ID. 생략 시 기존 작업비 시트 |

JSON 키는 저장소에 올리지 않습니다. 파일 방식은 `GOOGLE_APPLICATION_CREDENTIALS`도 지원합니다. 비밀번호·키·메모는 로그에 출력하지 않습니다.

Render Free는 유휴 시 중지될 수 있습니다. 진행 내용은 PostgreSQL에 보관하고 재시작 후 이어서 수집합니다. DB는 기존 HS 서비스와 자원을 공유합니다. 스키마 분리로 데이터는 구분하지만 부하와 장애는 공유합니다.

## 로컬 확인

Python 3.12 기준:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py runserver
```

조회·저장은 별도 터미널에서 `python manage.py runworker`를 실행해야 합니다. 운영의 실제 조회·시트 연결은 환경변수가 필요합니다. 로컬은 SQLite를 사용하며 운영은 PostgreSQL이 필수입니다.

앱 밖에서 원장 끝에 동시에 행을 추가하는 작업은 직전 재검사만 제공합니다. 여러 자동화가 같은 원장에 쓰게 되면 입력 원장을 분리해야 합니다. 중판 화면 구조·로그인 방식이 바뀌면 수집이 중단되며 0건·0원으로 처리하지 않습니다.
